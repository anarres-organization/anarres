# Security policy

Please do not open a public issue for a vulnerability that could expose credentials, enable sandbox escape, execute untrusted task code outside isolation, or materially weaken a verifier.

Until a dedicated security contact is published, report security concerns privately to the repository owners. Include the affected component, reproduction conditions, likely impact, and any known mitigation.

Never commit access tokens, private keys, cookies, cluster credentials, internal host inventories, or secrets embedded in experiment configurations.

Cybersecurity and biological integrations may require additional access controls and disclosure policies. Those domain policies can be stricter than this repository-wide baseline.
