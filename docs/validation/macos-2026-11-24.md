# macOS validation report

Anarres CLI 0.4.1 passed the recorded source-build, portable-record, adapter,
and Docker smoke checks on one Apple Silicon Mac on 24 November 2026. The
results support using the tested CLI workflows on that host. Actual policy
inference, training, and domain-specific scientific runtimes require separate
qualification.

## Scope and source identity

The initial run tested commit
`e27d473f224bc95e64e1f391dd49546b742dd1ea`. Supplementary source-install and
acceptance checks used a worktree based on
`5b4b8f29ccb990012531140be9aca106210fae8b`, with the acceptance script included
in this change. The intervening commit changes `docs/index.md`; application
code, dependency locks, schemas, and scientific contracts are identical between
those two revisions.

The [compact results](macos-2026-11-24.json) retain environment metadata, case
outcomes, source and binary digests, and the complete performance table. Raw
execution logs and generated records remain local under ignored directories,
consistent with the [artifact policy](../standards/artifacts.md). This report
does not reference an externally published log archive.

The initial run verified that all 1,481 tracked files retained their SHA-256
digests and that Git status remained clean. The report, compact results, and
portable acceptance script are subsequent additions.

## Method and acceptance criteria

Each command was evaluated using its exit status and, where applicable, its
JSON content, generated files, deterministic output, and overwrite behavior.
Negative cases pass when the expected rejection occurs and the relevant
postcondition holds. An exit code of 1 or 2 in such a case is expected.
Unhandled Rust panics and Python tracebacks fail the supplementary runner.

The test counts below describe executable cases and reproduction checks. Some
cover overlapping behavior or rerun nested tests; their sum is not a count of
independent observations. Reproducing released study records establishes
software reproducibility within those records' contracts. It does not add new
predictive or scientific evidence.

The reusable `tools/check_macos_acceptance.py` runner

The 97-case configuration also passed with Docker absent from `PATH`.

## Performance

The [performance runner](https://github.com/anarres-organization/anarres/blob/e27d473f224bc95e64e1f391dd49546b742dd1ea/tools/benchmark_cli.py) used three warmups and
20 timed samples for each of 32 scenarios. It required identical output bytes
across timed samples. Each invocation includes process creation and completion.
The reported p95 is the sorted sample at zero-based index
`ceil((n - 1) * 0.95)`.

| Scenario | Median | p95 | Samples |
| --- | --- | --- | --- |
| Native version | 2.418 ms | 2.788 ms | 20 |
| Native qualification | 2.487 ms | 3.175 ms | 20 |
| Native validation | 2.447 ms | 2.772 ms | 20 |
| Adapter discovery | 13.560 ms | 14.978 ms | 20 |
| Materials adapter doctor | 34.888 ms | 48.938 ms | 20 |

A separate 40-sample release smoke check measured version startup at a median
of 2.385 ms and p95 of 3.096 ms. These samples are a different run from the
20-sample table. The stripped release binary was 1,900,416 bytes, below the
2,250,000-byte guard. Adapter status medians ranged from 28.172 to 54.565 ms.

All guards passed: native paths and adapter discovery used a p95 limit of
50 ms, and other adapter paths used a median limit of 200 ms. These are the
repository's regression guards. The run used one host, no controlled power or
background-load protocol, and compact inputs. It supplies no confidence
intervals, cross-host comparison, or large-data throughput claim. See the
[performance guide](../performance.md) for the maintained methodology.

## Docker observations and test corrections

Real containers exercised `hello-world`, a digest-resolved Alpine image,
read-only root filesystems, a writable tmpfs, removed capabilities,
`no-new-privileges`, and bounded memory and process counts. Memory and process
limits were read back from cgroup files. A one-CPU limit was requested; its
quota was not separately asserted. Network checks observed no default route
and no global IPv4 or IPv6 addresses under `--network none`.

A bind mount containing Unicode characters and spaces supported host-to-container
reads and container-to-host writes. A Dockerfile containing a synthetic text
fixture built and ran successfully. Containers used `--rm`, and the locally
built test image was removed. These observations concern generic Docker
operation, rather than qualification of a pinned Vero or other domain image.

The initial platform run passed 12 of 13 cases. Its failed assertion assumed
that `--network none` exposes exactly the loopback interface. The LinuxKit
kernel also exposed unconfigured tunnel interfaces. Diagnostic execution
confirmed the expected capability, privilege, and filesystem controls. The
network assertion was corrected to test routes and global addresses; the final
platform run passed 13 of 13 cases. No Anarres implementation or Docker
configuration was changed to obtain that result.

The local recorder initially used overlapping filenames for stage metadata and
some result files. Stage metadata was subsequently separated, performance data
was recovered from the original command output, and CLI/platform evidence was
recaptured. Final counts use those corrected records; initial logs were
retained locally.

## Reproduction

Run from a macOS checkout with Rust, uv, and a running Docker Desktop available.
The commands below install the declared optional test dependencies and adapters.
Use a new acceptance output directory on each invocation. The Docker option
pulls public images and creates synthetic test files and a temporary image.

```bash
uv sync --locked --all-packages --dev --group materials-test --group docs --python 3.12
uv python install 3.11
export PATH="$PWD/.venv/bin:$PATH"

make check
make study-check-extended
make materials-check
make docs
make release-smoke
make adapter-smoke
uv run python tools/benchmark_cli.py \
  --binary target/release/anarres \
  --output .anarres/macos-benchmark.json

cargo install --path crates/anarres-cli --locked \
  --root .anarres/macos-install --target-dir target
uv run python tools/check_macos_acceptance.py \
  --binary .anarres/macos-install/bin/anarres \
  --output-dir .anarres/macos-acceptance \
  --docker
```

Source installation and the supplementary acceptance run use the active
checkout; the initial result table refers to the pinned earlier revision.
Timing results and binary hashes may change with build paths, toolchains,
platform state, and source revisions. The compact result records the observed
binary identity without asserting a reproducible binary build.

## Limitations and remaining qualification

The tested population is one macOS 27.2.1 arm64 host and the named source
revisions. Intel Macs, other macOS versions, downloaded release archives,
Homebrew packaging, signing/notarization, and fresh-machine installation remain
unverified. The source-install check used an already provisioned toolchain.

Actual model inference, RL or scientific training, real molecular docking,
robot simulators, and the pinned Vero/Lean scientific runtime were not run.
Policy credentials and large model artifacts were unnecessary for these
checks. Those workloads need their governing protocol, source identities,
weights, target runtime, and evaluation contracts before execution. The bundled
fixtures and generic containers supply no evidence of downstream training
utility or of a domain runtime's scientific correctness.

Long-duration operation, concurrent stress, large raw-attempt datasets, and a
security audit were outside the test plan. Network-interface observations and
container controls are bounded smoke checks, with no claim of complete
containment assurance.
